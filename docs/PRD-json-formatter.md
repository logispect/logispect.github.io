| 项 | 内容 |
|----|------|
| 产品 | Tool Haven |

| 分类 | 开发（dev） |

| 文档版本 | v1.0 |
| 日期 | 2026-09-30 |

---

## 1. 背景与目标

在 Tool Haven 中新增第二个可用工具，面向开发者日常处理 JSON 文本的场景：粘贴一段 JSON，快速判断是否合法，并支持美化、压缩、一键复制。

**目标**

- 本地完成解析与处理，不上传、不落库。
- 首屏即可完成「粘贴 → 看结果 → 复制」主路径。
- 体验、视觉与密码生成器页一致（Graphite 配色、返回首页、限宽工具区）。

**非目标（本期不做）**

- JSON Schema / OpenAPI 校验
- JSON Path 查询、Diff 对比
- YAML / XML 互转
- 文件上传解析大文件流式处理
- 账号、云同步、历史记录云端存储

---

## 2. 用户与场景

| 角色 | 典型场景 |
|------|----------|
| 前端 / 后端开发 | 接口返回一坨挤在一行的 JSON，需要展开阅读 |
| 调试同学 | 不确定粘贴内容是否是合法 JSON，要快速报错定位 |
| 配置维护 | 改完 JSON 后压缩体积再贴回配置中心 |

主路径：打开工具 → 粘贴 → 自动或点击校验 → 格式化 / 压缩 → 复制。

## 3. 功能需求

### 3.1 输入区

| ID | 需求 | 优先级 |
|----|------|--------|
| F-01 | 提供多行文本输入框，占位提示示例：`在此粘贴 JSON…` | P0 |
| F-02 | 支持手动输入、粘贴；不限制字符类型 | P0 |
| F-03 | 提供「清空」按钮，一键清空输入与结果状态 | P0 |
| F-04 | 提供「粘贴」按钮：调用剪贴板读取并填入（权限失败时给出提示） | P1 |
| F-05 | 显示输入字符数（可选：字节粗估） | P2 |

### 3.2 合法性校验（是否合规）

| ID | 需求 | 优先级 |
|----|------|--------|
| F-10 | 使用浏览器原生 `JSON.parse` 判定是否为合法 JSON | P0 |
| F-11 | **合法**：状态条显示成功文案（如「合法 JSON」），使用强调色（accent） | P0 |
| F-12 | **非法**：状态条显示失败文案，并尽量给出错误信息（解析异常 message） | P0 |
| F-13 | 非法时尽量标注出错位置：行号 / 列号（若能从错误信息解析；解析不到则只展示 message） | P1 |
| F-14 | 输入为空时：不报「非法」，显示中性提示「请输入 JSON」 | P0 |
| F-15 | 校验触发方式：**输入防抖自动校验**（建议 300ms）+ 显式「校验」按钮 | P0 |
| F-16 | 仅接受标准 JSON：不把 JS 对象字面量（单引号、尾逗号、未加引号 key）当作合法 | P0 |

说明：「合规」本期定义为 **符合 JSON 语法（RFC 8259 / `JSON.parse` 可解析）**，不做业务 Schema 合规。

### 3.3 格式化（美化）

| ID | 需求 | 优先级 |
|----|------|--------|
| F-20 | 「格式化」按钮：合法时对对象/数组做缩进美化后写回输入区（或结果区，见交互） | P0 |
| F-21 | 缩进可选：2 空格（默认）/ 4 空格 | P1 |
| F-22 | 非法 JSON 时点击格式化：不改写原文，提示先修复错误 | P0 |
| F-23 | 格式化后保持合法状态，并更新字符数 | P0 |

### 3.4 压缩（Minify）

| ID | 需求 | 优先级 |
|----|------|--------|
| F-30 | 「压缩」按钮：去除无意义空白，输出单行 JSON | P0 |
| F-31 | 非法时同 F-22：不改写，提示错误 | P0 |

### 3.5 复制与导出

| ID | 需求 | 优先级 |
|----|------|--------|
| F-40 | 「复制」：将当前文本框内容写入剪贴板，成功给予短暂反馈（如「已复制」） | P0 |
| F-41 | 内容为空时复制：提示「没有可复制的内容」 | P0 |
| F-42 | （可选）「下载 .json」生成本地文件 | P2 |

### 3.6 辅助能力

| ID | 需求 | 优先级 |
|----|------|--------|
| F-50 | 示例按钮：填入一段演示用合法 JSON，便于首次体验 | P1 |
| F-51 | 快捷键：`Ctrl/Cmd + Enter` 触发格式化（可选） | P2 |
| F-52 | 大体积提示：输入超过约 1MB 时提示「可能较卡，建议分段处理」，仍允许继续 | P2 |

## 4. 交互与界面

### 4.1 信息架构

```
[ ← 返回 Tool Haven ]
标题：JSON Formatter
副文案：本地格式化、压缩与语法校验，数据不离开浏览器

[ 状态条：合法 / 非法 / 请输入 ]

[ 多行编辑区 ]

[ 校验 ] [ 格式化 ] [ 压缩 ] [ 复制 ] [ 清空 ]  （P1：粘贴、示例、缩进切换）

[ 简短说明 / FAQ ]
```

### 4.2 布局约定

- 与现有工具一致：hash 路由 `#json`，同页切换，避免 `file://` 跨页跳转问题。
- 工具页内容宽建议约 `720–880px`（JSON 编辑需要比密码页更宽）。
- 编辑区最小高度约 `280px`，可随窗口增高；等宽字体。
- 状态条固定在编辑区上方，颜色区分：成功 / 失败 / 中性。

### 4.3 状态文案（建议）

| 状态 | 文案示例 |
|------|----------|
| 空 | 请输入 JSON |
| 合法 | 合法 JSON |
| 非法 | 非法 JSON：Unexpected token …（截断过长 message） |
| 操作成功 | 已格式化 / 已压缩 / 已复制 |

### 4.4 首页接入

- 目录中 `JSON Formatter` 设为 `live: true`，`route: "json"`。
- 描述文案：`格式化、压缩与语法校验`。

## 5. 技术约束

| 项 | 要求 |
|----|------|
| 运行环境 | 纯前端，浏览器内执行 |
| 解析 | `JSON.parse` / `JSON.stringify` |
| 隐私 | 不发送到服务端；无第三方分析 SDK（本期） |
| 依赖 | 尽量零依赖；若行号定位需要可自写轻量定位，不引入大型编辑器（本期不做 Monaco） |
| 兼容 | 现代 Chromium / Firefox / Safari；需处理 Clipboard API 不可用时的降级提示 |
| 无障碍 | 按钮可键盘操作；状态变化可用 `aria-live` 播报 |

---

## 6. 验收标准

1. 粘贴合法 JSON → 状态为「合法」→ 格式化后缩进正确 → 压缩后为一行且仍合法 → 复制成功。  
2. 粘贴非法 JSON（缺括号、单引号、尾逗号等）→ 状态为「非法」并展示错误信息 → 格式化/压缩不覆盖原文。  
3. 输入框为空 → 中性提示，不显示「非法」。  
4. 从首页点击 JSON Formatter 可进入 `#json`；「返回」回到首页。  
5. 断网情况下（页面已加载）功能仍可用（字体除外）。  
6. 视觉符合 Graphite 主题，不引入新的紫色/深色体系。

## 7. 测试用例（摘要）

| 用例 | 输入要点 | 期望 |
|------|----------|------|

## 9. 开放问题

1. 格式化结果是**写回同一输入框**还是「左输入 / 右输出」双栏？  
   - **建议本期：单栏写回**，降低复杂度；双栏留到 v1.1 若有强烈需求再做。  
2. 是否支持 `JSON5` / 带注释的宽松模式？  
   - **建议本期：不支持**，严格标准 JSON，避免「看似合法实际不能给接口用」。  
3. Unicode / 特殊数字（`NaN`、`Infinity`）？  
   - 按 `JSON.parse` 行为：不支持则判非法。
